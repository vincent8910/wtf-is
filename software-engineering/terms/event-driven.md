# Event-Driven — 系統靠「事件」觸發動作

> **白話說：** 就像你設了鬧鐘——不是一直盯著時間看，而是時間到了鬧鐘響（事件發生），你才起床（執行動作）。Event-Driven 架構就是系統等著事件發生，再做對應的事。

---

## 它到底是什麼？

**Event-Driven（事件驅動）** 是一種軟體架構模式，系統的各個部分透過「事件」來溝通和觸發動作。

```
傳統方式（同步呼叫）：
  使用者下單 → 扣庫存 → 寄 email → 通知物流 → 回覆使用者
  （一步一步做，任何一步卡住全部等）

Event-Driven（事件驅動）：
  使用者下單 → 發出「訂單成立」事件
    ├→ 庫存服務收到事件 → 扣庫存
    ├→ 通知服務收到事件 → 寄 email
    └→ 物流服務收到事件 → 安排出貨
  （各自獨立處理，互不影響）
```

好處：
- **解耦**：各服務獨立，一個掛了不影響其他
- **可擴展**：新增功能只要「訂閱」事件就好
- **非同步**：不用等所有步驟做完才回覆使用者

常見工具：Kafka、RabbitMQ、AWS EventBridge、Redis Streams

## 生活比喻 / 實際例子

- **傳統架構** = 接力賽，一棒接一棒，中間斷了就停
- **Event-Driven** = 廣播系統，廣播一聲「開飯了」，各部門自己去吃

**造句**：
- 「我們的訂單系統是 **Event-Driven** 的，下單後各服務自己處理」
- 「改成 **事件驅動** 架構之後，系統的耦合度降低很多」
- 「用 Kafka 做 **Event-Driven** 架構，每秒能處理幾十萬筆事件」

## 為什麼要知道這個詞？

- [Microservice](microservice.md) 架構中最常見的溝通模式
- 高流量系統（電商、社群、遊戲）幾乎都是 Event-Driven
